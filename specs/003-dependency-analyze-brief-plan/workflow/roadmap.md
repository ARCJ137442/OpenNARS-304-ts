# 转译路线图

【ℹ️针对所有文件与模块，重点在描述清楚各文件夹（模块）转译的参考顺序（从基础无依赖到复杂多依赖，如：Term -> Item/Bag -> Concept/Task -> Memory -> Reasoner）】
【ℹ️在编写之前，请保证已阅读java-master/src/java/org/opennars的相关代码】

## 输入清单

- `deps.xml` 的模块与文件依赖关系。
- TS 代码中显式依赖（import/extends/implements 等）。
- Java 源文件的功能定位与关键结构。

## 产出格式

- 模块级链条：从基础模块到复杂模块的依赖顺序。
- 文件级顺序：在模块内按依赖关系细化到文件。
- 依赖来源标注：TS/Java graph。
【ℹ️路线图本身只生成一个，不分文件；生成的路线图，是后续逐个文件实现转写的参考顺序文档】

## 生成步骤

1. 从 `deps.xml` 提取模块间依赖，形成模块级链条。
2. 在每个模块内，按文件级依赖排序，补充 TS 中的显式依赖。
3. 标注“仅表面依赖”的关系，避免误导顺序。
4. 对每个模块链条给出最小可执行的起点与收尾。

## 校验标准

- 路线图顺序可被 `deps.xml` 复核。
- TS 与 Java 依赖不一致处有明确说明。
- 模块级链条与文件级顺序自洽，无循环或未解释的断点。
