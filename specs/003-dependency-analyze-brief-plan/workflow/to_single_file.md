# 单文件工作流

【ℹ️针对单个文件的转写工作计划，本质上类似于一个spec模板，可代入基本上任何未完成转写的TypeScript源码文件】

## 输入清单

- 目标 TypeScript 文件路径。
- 对应的 Java 源文件路径（java-master）。
- `deps.xml` 中的相关依赖片段。

## 工作步骤

1. 运行 `npx tsc <文件路径> --noEmit`，记录语法与缺失符号情况。
2. 基于语法与语义梳理 TS 依赖：
   - import/extends/implements/构造参数/静态成员引用。
   - 注意“仅常量引用造成的表面依赖”。
3. 对照 `deps.xml`，确认结构性依赖与表面依赖的差异。
4. 打开 Java 源文件，补写“从 Java 得来的功能描述”：
   - 目的/职责、关键数据结构、关键算法或不变量。
5. 列出行为一致性风险点：
   - 静态初始化、默认值、空值处理、继承链影响、序列化约定等。
6. 标注该文件在路线图中的位置与先后依赖。

## 输出模板

- 文件名与模块位置
- TS 依赖清单（结构性/表面依赖分列）
- Java 依赖清单（来自 `deps.xml`）
- 从 Java 得来的功能描述
- 一致性风险点清单
- 路线图位置与前置依赖

## 注意事项

- 只做分析与规划，不改动代码实现。
- 如依赖不一致，优先记录差异与原因，不强行合并。
