# 通用转写方法 1.0

目的：把 Java 风格模块转写为 TypeScript 的同时，保留核心语义、降低耦合并可验证。

## 核心原则

- 测试先行：先锁定行为，再动实现。
- 依赖降维：先切断高层依赖，再下沉实体。
- 语义优先：保留计算与约束，移除仪式化 Java 语义。
- 小步回归：每一步都能跑最小测试。

## 通用流程（8 步）

1) 依赖剥离
   - 低层模块不依赖高层模块：值对象/实体层不得直接依赖语言/控制/推理层。
   - 识别“表面依赖”与“结构性依赖”：仅用于展示/格式化的依赖应上移。
   - 高层需求通过适配器/格式化层实现：把转换/展示逻辑移到同层适配器或更高层。
   - 必须保留依赖时，显式在调用端引入，避免在基础类型中隐藏依赖。
   - 落地方式：在原文件同目录新增后缀文件承载迁移逻辑，例如：
     - `TruthValue.ts` → `TruthValueTerm.ts`（或 `TruthValueAdapter.ts`）
     - 规则：文件名保留原名 + 明确后缀，方便检索与溯源

2) 测试锁定
   - 先写测试覆盖核心行为与边界条件。
   - 测试应独立于 Java 语义（例如 StringBuilder/Serializable）。

3) 纯 TS 设计草案
   - 明确要保留的语义与边界条件，删除 Java 仪式性结构。
   - Java 语义 → TypeScript 替代清单：
     - `Serializable` → 移除；需要持久化时改为显式序列化函数
     - `Cloneable/clone()` → 显式工厂或 `copy()` 方法
     - `hashCode/equals` → 删除或改为 `toKey()` 字符串键
     - `java.lang.Math` → 原生 `Math`
     - `StringBuilder`/`CharSequence` → 字符串拼接或数组 join
     - `int/float/double` → `number` + 运行时校验
     - 构造重载 → 具名工厂函数
     - Java 异常类型 → `Error` 或自定义 Error
     - Java `enum` → TS `enum`；若带属性/方法则用 `const` 对象 + `as const`
   - 定义 TypeScript 风格 API：公共字段 + 最少 getter/setter（只在有逻辑时保留）。

4) 重写实现
   - 直接替换为纯 TS 类型与逻辑。
   - 把“计算/约束”留在 setter 或显式方法中。

5) 构造策略统一
   - 只保留“字段一一对应”的构造函数。
   - 其余构造逻辑改为具名工厂方法。

6) 调用点改造
   - 批量替换 `new` 用法与旧式 `get/set` 调用。
   - 保持调用点语义等价。

7) 运行期阻塞修复
   - 若测试因运行期依赖失败，先移除/内联常量或最小 stub。
   - 确保测试能跑通，再回头调整依赖结构。

8) 回归验证
   - 运行最小测试集。
   - 通过后更新 spec 状态与报告记录。

## 可复用清单

- 低层类对高层依赖的剥离点
- 行为测试覆盖范围
- 具名工厂函数命名规范
- 运行期依赖阻断策略

## 适用范围

- 值对象、实体对象、规则函数、配置类
- 依赖链较深、Java 语义负担较重的模块
