# 通用转译法

下列分节给出了 Java→TypeScript 转译中遇到的系统性差异以及统一的解决策略，供 `progress.md` 中的逐文件路线图引用。

## Control & Scheduling（控制与调度）
- Java 使用 `synchronized`、`wait/notify` 与多线程定时器控制推理循环，而 TypeScript 依赖事件循环。
- 采用显式的调度器对象：通过 `setImmediate`/`setTimeout` 驱动周期，维护一个可暂停的状态机结构来替代阻塞式循环。
- 将共享状态（Bag、Task 队列）封装到单线程消息中，必要时以 `AsyncGenerator` 模式暴露可迭代步骤。

## Entity & Serialization（实体与序列化）
- Java `Serializable`、`clone`/`equals`、`hashCode` 语义在 JS 中不存在。
- 用不可变对象（`readonly` 字段）配合工厂函数模拟值对象；提供 `copy()`/`toJSON()`，并集中实现 stamp/UUID 计算。
- 将长整型 (`long`) 统一映射为 `bigint` 或 `{ high, low }` 结构，确保比较/排序逻辑保持精度。

## Inference Rules（推理规则）
- Java 版本依赖大量静态表与重载方法（TruthFunctions、RuleTables、BudgetFunctions）。
- 在 TS 中以命名导出的 `const` 表、`Record<string, number>` 等结构重现，同时用联合类型约束输入。
- 对关键函数增加基于 `node:test` 的数值回归，覆盖浮点误差、NaN 路径。

## Interface Contracts（接口规范）
- Java 接口与默认方法需转成 TypeScript interface 或 abstract class，同时保持多继承关系。
- 为每个接口建立同名 `.ts` 文件，导出 interface/abstract class，并在实现端显式 `implements`，借助 `type` 别名替换 Java 的泛型通配符。

## IO & Event Pipelines（I/O 与事件管线）
- Java 依赖 `java.io.*`、`InputStream`、`OutputStream`、`Observer`／`EventListener`。
- 在 TS 中通过 Node `Readable`/`Writable`、`EventEmitter`、`AsyncIterable` 来实现；解析器（Parser/Narsese）使用生成器或 `for await` 处理流式输入。

## Language Layer（语言层）
- 语言层（Term/CompoundTerm/Statement 等）深度依赖 Java 泛型、继承树和静态缓存。
- 使用 TypeScript 的泛型约束、条件类型和 `readonly` 集合构建不可变结构；用 `Map<string, Term>` 统一缓存策略，避免全局静态变量。
- 对 equals/hash 逻辑编写集中测试，以 JSON 快照验证结构一致性。

## Main Runtime（主程序）
- Java `Nar`/`Shell` 通过线程启动、命令行参数和 `NarNode` 网络通信运行。
- 在 TS 中以启动容器（`NarRuntime`）封装 CLI 解析、配置加载和生命周期钩子，利用 Node `worker_threads` 或 `child_process` 代替内嵌线程。
- 入口文件暴露 `async start()`/`stop()`，方便测试阶段注入 mock I/O。

## Operators（操作符）
- Java 操作符依赖反射注册与 `Operation` 抽象，TS 需要显式引用。
- 建立统一的 `OperatorRegistry`，在构造时注入 `Memory`、`Task`、`Nar`；每个操作符暴露 `execute(memory, term, params)` 并返回 Promise，方便插入异步副作用。
- 在 mental/misc operator 上落地最小集成测试（伪造 Task/Memory）。

## Plugins（插件）
- Java 插件使用 ServiceLoader 或反射接入视觉/心理通道。
- TS 版本通过显式工厂与事件通道绑定（`PluginContext`），利用 `EventEmitter` 推送感知数据；对需要资源清理的插件实现 `dispose()`。

## Storage Structures（存储结构）
- Java 的 Bag/Memory 使用自定义容器与同步块，TS 中需要可观察的数组/堆结构。
- 使用 TypedArray/普通数组结合 `BinaryHeap`/`BucketQueue` 重现容量权重；在调试模式输出统计数据以验证 Distributor/Bag 行为。

## Util Layer（工具函数）
- Java `java.util.*`/`Collections`/`Arrays` 功能要手写或引用轻量库。
- 提供集中 `util/ListUtil.ts` 等模块，封装排序、去重、范围检查，并加上 `assert` 辅助函数以补全 Java 的防御式编程。

## General guidance
- 所有文件需在 `tsc --noEmit` 下保持零错误，缺失引用应尽量通过 `import` 明确化。
- 测试覆盖不足的模块至少应添加 `node:test` smoke test，或在 `npm test` 中注入 stub 以便未来扩展。
- 与 Java 源的差异建议通过对照 `java-master` 的行内注释记录在 `progress.md`，避免反复比较。
