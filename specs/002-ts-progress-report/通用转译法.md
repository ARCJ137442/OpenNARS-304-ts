# 通用转译法 (Java -> TypeScript)
此节统拘 Java 与 TypeScript 之间的系统差异，以便 situation.md 和 progress.md 的路线图可以引用固定的基准。

## Control & Scheduling (控制与调度)
- Baseline: Java runtime relies on synchronized/wait/notify and Thread loops; TypeScript must lean on Node's event loop plus Promise control flow.
- 转译策略: 重建推理循环、任务调度与暂停机制，替换 synchronized/wait 行为。
- Java→TS: 参见《通用转译法.md》 - 控制与调度
- Verification: Add node:test smoke tests that cover pause/resume cycles and priority switching inside Nar/NarNode/Scheduler.

## Entity & Serialization (实体与序列化)
- Baseline: Java uses Serializable, clone, equals/hashCode, and 64-bit primitives for value semantics; TS lacks these built-ins.
- 转译策略: 保持 Stamp/TruthValue 等值对象的不可变语义，补齐 clone/equals/hash 与序列化。
- Java→TS: 参见《通用转译法.md》 - 实体与序列化
- Verification: Provide clone/equals/hash fixtures and JSON round-trip cases to match Java's signed width expectations.

## Inference Rules (推理规则)
- Baseline: TruthFunctions, RuleTables, and BudgetFunctions rely on static tables plus overloading in Java.
- 转译策略: 复制规则/真值/预算静态表并完善类型约束与数值校验。
- Java→TS: 参见《通用转译法.md》 - 推理规则
- Verification: Back each rule with node:test regression vectors comparing the TS outputs to the Java baseline.

## Interface Contracts (接口规范)
- Baseline: Java interfaces allow default methods and multiple inheritance; TS needs explicit interface/abstract hierarchies.
- 转译策略: 以 interface/abstract class 还原 Java 接口，在 TS 实现类中显式 implements。
- Java→TS: 参见《通用转译法.md》 - 接口规范
- Verification: Use tsd/type-guard assertions so every implementation satisfies the expected structural contract.

## IO & Event Pipelines (I/O 与事件链路)
- Baseline: Java depends on java.io plus Observer/EventListener; TS must use Node streams and EventEmitter to transport data.
- 转译策略: 将 java.io 流与事件转接到 Node 流 + EventEmitter，补宏 Parser/Narsese/Events 链路。
- Java→TS: 参见《通用转译法.md》 - I/O 与事件
- Verification: Replay parser/event fixtures to ensure Node stream outputs line up with Java InputStream behavior.

## Language Layer (语言层)
- Baseline: Term/Statement/CompoundTerm use Java generics and static caches to enforce type strata.
- 转译策略: 维持 Term/Statement 层的泛型层次和不可变结构，同时统一缓存策略。
- Java→TS: 参见《通用转译法.md》 - 语言层
- Verification: Author equals/hash/unify combo tests covering the major term families to guard cache consistency.

## Main Runtime (主程序)
- Baseline: Nar, NarNode, and Shell depend on Java threads, CLI parsing, and sockets.
- 转译策略: 把 Nar/NarNode/Shell 生命周期、线程和 CLI 搭到 Node 异步控制器上。
- Java→TS: 参见《通用转译法.md》 - 主程序
- Verification: Simulate CLI input/output with node:test to confirm lifecycle hooks and worker orchestration mirror Java.

## Operators (操作符)
- Baseline: Java registers operations via reflection; TS needs explicit OperatorRegistry wiring and dependency injection.
- 转译策略: 将 Operation 注册与 Memory 交互显式化，补写副作用与预算更新。
- Java→TS: 参见《通用转译法.md》 - 操作符
- Verification: Write task-execution samples for each operator to confirm side-effects (task creation, budget updates) match.

## Plugins (插件)
- Baseline: Java loads plugins through ServiceLoader and reflection-based factories.
- 转译策略: 为心理/感知插件提供事件通道、状态缓存与关闭流程。
- Java→TS: 参见《通用转译法.md》 - 插件
- Verification: Drive plugin lifecycle with a fake PluginContext, replaying event/input samples to ensure determinism.

## Storage Structures (存储结构)
- Baseline: Bag, Memory, and Distributor enforce capacity/order via synchronized blocks in Java.
- 转译策略: 验证 Bag/Memory/Distributor 的容量、顺序与线程安全，补完断言和测试。
- Java→TS: 参见《通用转译法.md》 - 存储结构
- Verification: Extend node:test beyond Distributor.ts to assert bag sampling, memory eviction, and distributor ordering.

## Util Layer (工具层)
- Baseline: java.util/*, Collections, and Arrays supply helpers missing from TS.
- 转译策略: 整合 java.util 工具并保持 int/long 行为一致，中心存放工具函数。
- Java→TS: 参见《通用转译法.md》 - 工具层
- Verification: Exercise edge cases for list/array/number helpers—especially sampling/sorting—to match Java semantics.

## Testing & Tooling (测试与工具链)
- Baseline: Only storage/Distributor.ts has node:test coverage today; historical Chinese docs suffered mojibake.
- 转译策略: 每个包至少补充一个 smoke test，CI 需要固定 `npx tsc --noEmit` + `npm test` 测试线，同时出关 hanzi 编码报告。
- Java→TS: 关注系统转译中的编码/语言环境差异，每次修改隐含中文的 Markdown 都要基于 hanzi-report.json 复检。
- Verification: Automate hanzi encoding checks and keep npm scripts green before sending PRs.
