## 任务过程笔记

- 直接比较 Task/Sentence 文本会把 Java 和 TS 的运行时 Stamp 长 ID误判为语义差异；直接 `String(term)` 会把 jree Term 变成 `Conjunction@...` 等对象身份。两者都必须在观测层规范化，不能修改业务对象。
- NAL 数字行会把输入分割成多个“输入 → 内置周期 → 新输入”阶段。stage digest 必须逐段记录 pre，否则会在已 finalize 的哈希上继续写入，产生观测器自身异常。
- `detective2` 完整夹具的 120 秒结果显示：在已完成的 3072 周期共同前缀内，Task/Concept/Link/Scheduler/Rule/Derivation/Marker 阶段均一致；当前证据支持“超时发生在更高周期或吞吐/任务规模范围”，但还不能排除 3072 之后分叉。
- stage digest 的 marker 阶段只记录 OUT/EXE 事件计数和摘要，不替代 `outputMustContain` marker 判定；长周期等价仍必须先通过正式 marker gate。
- 本批长测试指标：`long_test_count=2`（marker 回放、流式 stage digest），`programmatic_blocking_supported=true`，`model_visible_poll_count=3`，`empty_poll_count=0`，`early_stop_count=0`，`productive_wait_tasks_completed=0`。TS 是达到明确 timeout 后停止，不是提前猜测停止。
