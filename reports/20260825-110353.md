## 任务过程笔记

- Java 的“字段默认 null”在 TS 中不能通过 `null as unknown as T` 伪装为非空；需要把对外 getter/使用链的类型契约一并表达出来。
- `Operation.task` 的 definite-assignment 诊断不是性能或运行时错误，而是 TS 对 Java 默认字段初始化语义的静态提醒；本批通过 nullable getter 与 `requireTask()` 将“尚未登记”和“此处必须存在”分开表达。
- `Term.name` 的 null 不是错误状态：Java 的 `CompoundTerm.invalidateName()` 主动把缓存置空，随后 `CompoundTerm.name()` 再创建。内部 getter 必须可空，公共方法只在需要保持既有接口时做边界收窄，不能把 null 直接变成 NPE。
- `Believe` 的处理依据是 Java `TruthValue.fromWordTerm` 的实际返回契约；不能只根据当前一行错误机械加断言。
- 首次 1024 MB tsc 尝试触发本机 `EXCEPTION_ACCESS_VIOLATION`，没有产出诊断证据；改用 768 MB 串行重跑成功。该现象记录为主机稳定性问题，不作为源码失败。
