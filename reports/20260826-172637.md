## 修改内容汇总（git diff 行级）

本批修改围绕同一因果链：核心声明可选系统命令能力，Node 入口提供实现，配置层在能力缺失时给出独立记录，测试锁定两种边界。

### `src/platform/RuntimeCapabilities.ts`

- 定义核心可依赖的可选 `executeSystemCommand` 能力。
- 定义稳定的 `MISSING_RUNTIME_CAPABILITY` 错误。

目的：让核心不再直接依赖 Node 进程 API。

### `src/platform/node/SystemCommandCapabilities.ts`

- 以 Node `execFileSync` 提供 Java 兼容的 `bash -c` 实现。
- 将 stdout 返回给核心并捕获 stderr。

目的：把进程能力限制在 Node 宿主边界。

### `src/operator/misc/System.ts`

- 删除 `node:child_process` 直接导入，改为使用注入能力。
- 无能力时抛出明确错误；有能力时保留原有 stdout 拼接行为。

目的：保持 `^system` 行为，同时切断核心到 Node 子进程模块的依赖。

### `src/io/ConfigReader.ts`、`src/main/Nar.ts`

- 将运行时能力沿配置加载和 `Nar` 构造边界传递。
- 对已知但缺少宿主能力的插件单独记录 classpath。

目的：配置行为可诊断、能力依赖显式化。

### `scripts/converting/audit-platform-boundaries.mjs`

- 将 `src/platform/node/` 正确归类为 Node 宿主适配器，而不是核心候选。

目的：让平台边界审计的分层结果与目录架构一致。

### `src/index.ts`、`src/public-api.d.ts`

- 导出能力接口及缺失能力错误，并同步公共构造选项类型。

目的：Node、浏览器和其他宿主都使用同一公共能力契约。

### `scripts/cli.mjs`、`scripts/shell.mjs`、`src/main/Shell.ts`

- 三个 Node/兼容入口显式创建并注入 Node 能力。

目的：保持现有 CLI 与 shell 的可运行行为，不让核心隐式探测宿主。

### `test/node/system-operator.test.ts`、`test/node/config-platform-boundary.test.ts`

- 覆盖能力存在、能力缺失、配置跳过和独立观测字段。

目的：防止后续去平台化时静默改变 `^system` 或插件配置语义。
