## 任务过程笔记

- jree 的 `java.lang.Comparable<T>` 并非只声明 `compareTo`，还继承反射接口；对已脱离 JavaObject 的值对象继续实现它会把不需要的 `getClass` 类型要求带回调用链。
- “保留 Java 方法”与“保留 jree 接口实现”是两个不同层次：本批保留 `compareTo` 方法和自然排序合同，但移除接口壳，并在算法边界显式调用比较器。
- `equals` 参数使用 `unknown` 更符合原 Java 的“可与任意对象比较”入口，也允许同一值对象之间进行类型安全的值比较。
- 这类数据壳的原生化不能只按 API 形状判断；必须同时检查 Java 的排序、集合去重、哈希和文本消费路径。

## 修改内容汇总（git diff 行级）

### `src/entity/Stamp.ts`

- `BaseEntry` 原 Java 类型为 `public static class BaseEntry implements Comparable<BaseEntry>, Serializable`；本批删除只提供反射/marker 能力的 jree 壳，保留 `narId`、`inputId`、访问器、值相等、Java 31 倍哈希和 `compareTo` 的顺序。
- Java 的 `Arrays.sort(set)` 改为原生数组排序，并显式调用同一 `compareTo`；这不是把排序算法改成另一种顺序，而是把自然排序合同从 jree 接口实现中解耦出来。
- `toString()` 返回原生 `string`，文本格式仍为 `(<narId>,<inputId>)`；`equals` 接受 `unknown`，先做身份和 `instanceof` 判断，再按两个 long 字段比较。

- 保留原有 evidential-base、重复值和 `ProcessGoal` 回归，并增加 `BaseEntry` 原型链、`compareTo`、`toString` 和相等值哈希一致性断言。

上述改动的目的，是消除 jree `Comparable<T>` 对 `IReflection/getClass()` 的类型传播，同时不改变 Java `BaseEntry` 在排序、去重和哈希中的可观察语义。
