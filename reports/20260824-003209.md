## 任务过程笔记

- 📌 Java → TypeScript 的字符串拼接不是普通类型转换细节：Java 对象拼接调用对象文本表示，而 JS 默认可能使用运行时对象标识。对 Narsese、Term、Truth、Budget 等对象，生成输入前必须显式调用项目定义的 `toString()`/规范化文本函数。
- 📌 现有视觉测试只断言完整矩阵后的 `cnt_updated=0` 和空 subject；旧实现即使完全没有进入视觉通道，也可能碰巧满足这个最终状态。本批将断言前移到首个像素：`cnt_updated=1`、`subj=M1`，再补完整矩阵收满路径，避免“最终状态碰巧归零”的假通过。
- 📌 `import type` 只能用于静态类型位置。只要 Java 翻译保留 `new Task(...)`、`instanceof` 或静态方法调用，就必须确认对应符号有运行时 import；这类问题会被上游派发分叉掩盖。
- 📌 阶段摘要比最终 marker 更适合定位首个分叉：修复前的 `vision.nal` pre-stage 计数直接指出输入登记链，而不是把后续 marker 缺失归因到推理规则。
- 📌 本批 TypeScript 8192 周期阶段摘要耗时约 `178287 ms`，Java 约 `1505 ms`。两边均有周期/事件进展；这是性能观测，不是 timeout，也不改变本批功能结论。性能优化留到逻辑差异收敛之后。
