## 本批假设卡

### 已证实事实

- Java `AbstractTerm.java` 是 `interface AbstractTerm extends Cloneable, Comparable<AbstractTerm>`。
- Java `Term` 明确声明 `implements AbstractTerm`，并以 `compareTo(AbstractTerm)` 实现比较契约。
- TypeScript 原实现却把它写成继承两个接口的抽象类，且 `name()` 在 abstract 方法上保留了非法实现体。
- 当前基线非增量 tsc 为 `1469（生产573，测试896）`；相关诊断包含 `TS2689`、`TS1174`、`TS1245` 和 `TS2459`。

### 尚未证实的假设

- 该错误的主要影响是静态接口闭合；把接口和比较器参数恢复为 Java 形状不应改变运行时行为。
- 这一批不会解决 `Image.ts` 中现存的 `NativeOperator` 类型别名错误，也不把其混入本批。

### 可证伪实验

- 将 `AbstractTerm` 改为导出的 TypeScript interface，保留 `Cloneable`/`Comparable` 关系；让 `Term` 实现该接口，并将 `Term`、`CompoundTerm`、`Variable` 的 `compareTo` 参数统一为 `AbstractTerm`。
- 重新运行非增量 tsc、串行单元测试和 canonical Java 局部 parity；若运行时结果变化或出现新增非相关诊断，则撤回或拆分该修复。

## 任务过程笔记

- Java interface 的默认方法不能机械转成 TypeScript abstract class；接口继承关系、可见性和默认方法体必须分别映射。
- `java.lang.Cloneable` 与 `Comparable<T>` 在 jree 中是 TypeScript interface，正确关系应使用 `extends` 于 TS interface，而不是 class `extends`。
- Java `compareTo(AbstractTerm)` 是语言层公共契约；仅把 `AbstractTerm` 改为 interface 仍会留下 `Image.super.compareTo` 类型分叉，必须同步调整继承链的参数类型。
- 当前 Node/jree 的弃用警告仍存在，属于 M2 后续公共运行时边界债务，不是本批根因。
