## 任务过程笔记

- Java 工厂方法的“理论上正常、异常时返回 null”必须在迁移后的类型合同中显式表达，否则错误会从语言层向推理规则层扩散。
- 对 `null` 的正确处理不是统一抛异常：当前 Java 下游多是“无可派生任务则返回”，因此各规则应在任务派发边界跳过空结果，保持推理控制流。
- `Statement.make` 的可空签名会暴露许多历史代码依赖的隐含不变量；本批只补直接受影响的调用点，不把其他既有诊断混入。
- 测试通过与诊断下降不能替代 M1 功能偏移验收；18xx 门槛仍以提交后的权威非增量统计为准。

## 修改内容汇总（git diff 行级）

本批只包含 Statement 可空合同及其直接消费者；`TruthFunctions.ts`、`Image.ts`、`Nar.ts`、`VisionChannel.ts` 和 `tsconfig.tsbuildinfo` 等工作区既有修改不纳入本批。

### `src/language/Statement.ts`

- 将 `NativeOperator` 别名改为 `Symbols.NativeOperator`，消除不适用于该运行时对象的 `InstanceType`。
- 为四种 `make` 重载、实现体及 `makeSym` 增加 `Statement | null` 返回合同。
- 目的：准确表达 Java 304 的非法关系、重叠项或未知操作符返回空值的行为。

### `src/inference/CompositionalRules.ts`

- 将两个由 `Statement.make` 产生的 `content` 标记为 `Term | null`，沿已有空值返回路径退出。
- 目的：避免把未成功构造的语句送入后续预算与任务生成。

### `src/inference/LocalRules.ts`

- 将关系转换结果标记为可空，并在连续变量替换前检查前一步是否已经失败。
- 目的：保持 Java 的无结果短路语义。

### `src/inference/StructuralRules.ts`

- 将结构变换中的语句、复合项结果标记为可空，复用已有空值检查。
- 目的：让结构规则在工厂返回空值时安全停止，不改变正常派生路径。

### `src/inference/SyllogisticRules.ts`

- 将派生内容变量改为可空。
- 对直接传入 `doublePremiseTask` 的相似、继承、对称、类比和相似性结果增加显式非空守卫。
- 目的：避免非法语句进入任务派发，同时保持正常关系派生顺序。

### `src/io/Narsese.ts`

- 将解析得到的语句标记为可空，保留已有的无效输入异常分支。
- 目的：使解析层完整承接 Java 工厂的失败合同。
