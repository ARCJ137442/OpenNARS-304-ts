## 任务过程笔记

- jree `HashMap`/`HashSet` 使用 immutable 后端和 Java equality comparator；因此当前高风险不是所有 Java 集合，而是少数原生 JS `Map`/`Set` 与对象 key 的身份语义。
- `as float` 在 TypeScript 中是编译期断言，不能实现 Java 的运行时 binary32 收窄；应继续使用 `Math.fround` 或集中化的 `Float32Math`。
- runner 的异常文本不能替代进程状态；Node experimental warning 可能出现在 stderr，但不代表真正的退出原因。
- 过程安全限时只能说明本次运行尚未完成；它与无进度 watchdog、marker 缺失和逻辑分叉必须分别记录。
- 既有 runner 语义测试原先把 `process_limit` 断言为无分类；该断言已按当前验收口径改为 `process_limit + performance_warning=true`。
- 参照同级 `NARust-158` 的模块组织，其顶层顺序明确区分全局/符号/参数、语言、实体、存储、推理、控制和入口 VM；推理模块内部再分 traits、数值函数、预算推理、本地推理、engine、rules。后续 TS 模块整理应借鉴这种依赖方向，但不在本批次扩大重构。
