# 20260825-020212

## 上一报告回顾

上一报告：`20260825-015203.md`

上一批以显式 `JavaDoubleCompat` 隔离 jree 缺失的 `java.lang.Double`，诊断降至 1666，串行单测、局部 parity 和 3 个 NAL 样本通过，提交 `24372b4` 已推送。本批处理 jree 缺失的 `System.identityHashCode`。

## 已确认事实

- jree `System` 没有 `identityHashCode` 静态 API。
- Java `Variable` 在比较变量 scope 时调用 `System.identityHashCode`；这里需要的是对象生命周期内稳定、按引用区分的整数，而不是对象自身 `hashCode` 或内容 hash。
- 当前工作树基线为 1666 项：生产 740、测试 926；canonical Java artifact 未改变，SHA-256 为 `2CF519E1F85C38E38384C7076AA750C730580C612C97CC70C70B361361F273F5`。

## 本批决策

- 在 `jree-compat.ts` 增加基于 `WeakMap<object, number>` 的 `javaIdentityHashCode`，对 null 返回 0，并为同一对象复用同一编号。
- 仅替换 `Variable` 的两个已确认调用点；不修改 jree 第三方 namespace，不把 identity hash 与内容 hash 混用。
- 增加直接回归测试验证 null、稳定性和不同对象的区分。

## 任务过程笔记

- `identityHashCode` 的兼容实现必须是引用身份表；使用 Java `hashCode` 或 JavaScript 原生对象内容转换都不能表达该合同。
- `WeakMap` 不阻止对象回收，适合只要求对象存活期间稳定编号的运行时边界。
- jree ESM `main` 字段弃用警告仍存在，但不是本批引入。
