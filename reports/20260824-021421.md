## 已证实事实

- fixture 含 `200000` embedded 周期和 `1550` extra 周期，具有两个明确 marker。
- Java 在 4966 ms 完成，两个 marker 均命中，`2/2`。

- TypeScript 在安全上限内没有返回 marker；`ts_marker_missing=true`，两个 marker 均未命中，combined `parity=false`、`functional_pass=false`。
- 运行结果为 `process_limited=true`，不是 no-progress timeout；当前不能把它判定为 scheduler、TermLink、RuleTables 或数值语义分叉。
- 既有 `toothbrush2` 8192 周期、跳过 embedded 的阶段摘要 Java/TypeScript 一致；该证据只覆盖共同短窗口，不能覆盖本次 200000 embedded 状态。

## 结论与待验证假设

- 当前最强结论是“TS 在 toothbrush2 的高周期 marker 前持续推进但吞吐不足或状态规模增长过快”；这是性能/可观测性事实，不是功能等价结论。
- 尚未验证的两种主要假设：
  1. TS 与 Java 在高周期状态仍保持语义一致，只是 TS 无法在合理安全预算内抵达 marker。
  2. 两侧在某个高周期窗口出现调度、任务增长、TermLink 或规则分派的首个分叉，导致 TS 后续状态增长不同。
- 下一项最小实验：不再提高同一种完整 marker 运行的安全上限；增加低开销、按窗口计数的 Java/TS 阶段观测，在 `8192 → 32768 → 65536 → 131072` 周期窗口比较 Task、Concept、TermLink、Rule 和 marker 计数，先定位首个不同窗口。
