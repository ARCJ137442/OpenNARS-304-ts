## 任务过程笔记

- `java.util.Random` 的 48 位 LCG 和 `nextInt` 序列已验证一致；这次分叉不是随机算法或 Float32 造成的。
- 容器语义必须区分“成员相等/哈希去重”和“插入顺序迭代”两个契约；jree 两者都不能直接按 Java 假定使用。
- Java `ImmutablePair` 的 `equals/hashCode` 是推理结果集合去重的一部分，不能用只提供 getter 的普通对象替代。
- Float32 仍需作为独立数值边界持续维护；本批不把非数值的变量顺序问题强行归入 Float32 修复。
- Windows 下 `child.kill()` 不能可靠终止带 loader 的 Node 子树；runner 超时隔离必须使用 `taskkill /PID /T /F`，否则分块结果不会落盘。
