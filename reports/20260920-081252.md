### 1. 本批修改：J3 数学浮点边界

代码提交：`cd33361 refactor(023): 收敛J3数学浮点边界`，基线为
`fb9a7dd`。

- `src/runtime/Float32.ts` 新增 `Float32Math.powDouble`。它先把 Java
  `float` 输入收窄为 binary32，再以 Java `Math.pow(float,double)` 的 double
  结果返回；只有调用方把结果存入 float 时才收窄，避免提前 `Math.fround`。
- `src/inference/BudgetFunctions.ts` 将 `sqrt` 的 double 计算与 float 局部赋值
  分开；`applyForgetting` 使用 `powDouble`，保持 Java 的 widening/narrowing
  边界。
- `src/inference/CompositionalRules.ts` 的 `Math.pow(2.0,i)` 改为原生 double
  计算，保留 Java double 比较语义。
- `test/node/float32.test.ts` 增加 double 结果不应提前收窄的回归。

这是一个语言数值语义切片，不是性能优化，也没有顺手重写推理规则。

## 从头到尾的进度与方法

项目目标不是“把 Java 文本机械改写成 TypeScript”，而是构建一个可运行、可测试、
可维护，并在已定义观测面尽量保持 OpenNARS 3.0.4 行为的 Node.js/TypeScript
推理内核。方法被拆为四层：

1. 先固定 canonical Java 304 源码、JAR、哈希和单线程运行口径。
2. 用 M1 marker/parity/markerless 长周期矩阵固定可观察行为，用 M2 测试、非增量
   typecheck、build、dist API 固定 TypeScript 结构正确性。
3. 对照 Java 声明、调用面和可观察语义，逐责任簇把 jree 边界收窄；List、Set、Map
   不混用，Java equals/hashCode、顺序、null、迭代删除和运行时身份单独验证。
4. 责任簇稳定后再跑 M1-；023/024 里程碑级验收才现跑 Java、完整 245+1、M2、CLI/API
   和平台证据。性能只记录“运行时长/推理周期”和 RSS，放到功能稳定后优化。

阶段演进：

- **013/018/019 基础门**：固定 Java canonical、M1 功能观测和 M2 零诊断构建。
- **G0 之后**：先迁移短生命周期数组、文本 Map、operator registry、atom cache、
  变量重命名表等低风险边界。
- **J2**：逐批处理 List 专有语义，包括可变副本、固定大小视图、迭代器和删除重载。
- **J2/J3**：处理 Term 值相等去重、插入顺序、Map value Set、递归组件和嵌套 Set。
- **当前 J3**：先完成 `powerSet` 的 `Set<Set<T>>` 边界，再收敛 float/double
  数值边界；本批没有扩大到规则族重写。
- **后续 J1/J3**：拆解 `jree-compat.ts` 的异常、字符串、类 token、数值和集合桥接
  责任，只有调用者合同迁出后才删除对应桥接。

## 任务过程笔记

- Java `Math.pow(float,double)` 的关键不是“所有数字都 `Math.fround`”，而是先在
  float 输入边界收窄，再保留 double 结果直到 Java float 变量赋值处；这类聚合函数
  适合放在 `Float32Math` 中并单独测试。
- 旧 Java JSONL 标杆适合普通小簇的 TS-only 验证；Java 源码、canonical JAR、阶段
  spec 或验收协议改变时，才重新运行 Java 并刷新标杆。
- `jree-compat.ts` 不是可直接删除的冗余文件，而是迁移过渡层；其异常、字符串、
  类身份和 null 规范化都有可观察调用者。
- 当前 5 个样本均无功能回退；性能只作为观测，未据此修改推理算法。
- 临时证据 JSONL 已放项目外，仓库不吸收大体量 trace 或构建产物。
