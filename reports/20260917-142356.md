## 任务过程笔记

### 新经验

- `Anticipate` 的 Set value 不是数组候选：Java 代码明确通过 `terms.iterator()` 遍历并在条件满足时 `ii.remove()`，因此原生实现必须提供 Set 语义与迭代删除契约。
- NativeSet 的 `[Symbol.iterator]()` 仍返回可供 `for...of` 使用的迭代器；新增显式 `.iterator()` 只承担当前 Java 调用点需要的 `hasNext/next/remove`，避免把所有调用强行伪装成完整 jree `Iterator`。
- 外层 `anticipations` 仍是 Java `LinkedHashMap`，本批只替换其值对象；Map 的 key equality、entry iterator.remove 和生命周期不属于本批已验证范围。
- 旧提交中的 List→数组转换继续以调用面判断：无 `.size/.get/.add`、值相等删除、迭代器删除或公共 List 形状依赖时，数组仍是优先结果；该原则不适用于 Set。
- 共享容器的“原生化”不能只对比 API 名称：Set 还要审查值相等、插入顺序、迭代器删除和并发修改观察面；本批因此把 iterator contract 作为 NativeSet 的一部分补齐。
- 本批暴露了一个此前未命中的交界问题：jree `LinkedHashMap` 的 entry iterator 不支持 Java `remove()`。修复时保留 Map 抽象，只延迟收集待删 Prediction，再调用 Map `remove()`；这不是把 Map 降成数组，也不是修改推理规则。
