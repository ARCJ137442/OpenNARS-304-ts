## 修改内容汇总（git diff 行级）

### `src/language/Term.ts`、`CompoundTerm.ts`、`Variable.ts`

- Java 原始返回形状：`Map<Term, Integer>`，实现：`LinkedHashMap`。
- 当前实现：`MapContract<Term, int>`，内部为 `NativeMap`；只将计数 value 从 boxed Integer 改成原生数值，Term key、判等、哈希和插入顺序不变。
- 目的：移除计数路径对 `java.lang.Integer.valueOf` 的运行时依赖，避免把 Map/Set 语义误降级为数组或普通 JS identity Map。

### `src/inference/CompositionalRules.ts`、`ProcessGoal.ts`、`ProcessJudgment.ts`

- 将计数调用方的默认值和类型同步为 `0`/`int`；变量引入、目标概念和前提收集算法没有改写。
- 目的：验证 J3 推理路径能够消费原生计数值，同时继续使用 `NativeMap` 的 Java 值语义。

### `test/node/core-runtime.test.ts`

- 新增断言：递归计数的 Map value 在运行时为 `number`，并继续保持数量与 key 顺序。
- 目的：锁定“值原生化、容器合同不变”的边界。
