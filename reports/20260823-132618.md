## 任务过程笔记

1. Java `float` 规则不是“最终赋值时 fround 一次”：若两个操作数均为 float，Java 会先以 binary32 保存操作数，再以 float 规则完成中间运算。该边界会直接改变 Bag level、预算排序和 belief selection。
2. 不能把所有 Java `number` 都改成 Float32Math。Java 原式含 double 时必须保留 binary64 计算，只在 Java 的显式 cast、float 局部变量或 float 字段写入处收窄；`PROJECTION_DECAY` 是本批次的反例。
3. Java float 字段若在 TypeScript 中保留为可直接写入的 number，仅靠调用点的 `as float` 不足以保持契约；TruthValue frequency、BudgetValue 字段和插件参数需要在 setter/构造边界再次收窄。
4. marker 标准与性能标准必须分离：有 marker 且双方 marker 均满足 expected 时，不要求额外达到 131072 周期；没有 marker 时，当前结果只能标记为未验证，不能用“跑满周期”替代 marker。
5. 30 秒屏幕适合作为吞吐预警，不适合作为逻辑失败的唯一证据。后续对关键样本应保留逐文件超时、marker 时间戳、Java/TS 线程模式、artifact hash 和实际推理周期。
