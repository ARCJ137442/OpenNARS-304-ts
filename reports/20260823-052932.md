## 任务过程笔记

- Java `float` 的关键不是只在最终赋值点调用 `Math.fround`，而是保留每个 Java `float` 操作数进入运算前的单精度状态。`Float32Math` 因此是未来逐点迁移的聚合边界，不是对全部 `number` 的机械替换。
- Java 的方法重载在 TypeScript/JavaScript 运行时不会按签名自动分派。子类的无参 `hasVar()` 会遮蔽父类的 `hasVar(type)`；如果不显式按参数数量转发，错误不一定立即抛出，而可能通过随机顺序改变推理轨迹。
- 随机数状态是高信息量观测面：一次多余的 `nextInt` 就能把后续集合 shuffle 全部错位。因此“最终结果看起来相同”不能替代随机调用次数和首个分叉事件的对照。
- `toothbrush2` 的 256 周期全轨迹一致说明本次重载修复足以消除该样本的已证实差异，但不能外推到其它未知样本或 245+1 全量矩阵。
- 本批一次错误路径参数生成的 v4 证据和 v5 旧轨迹均未作为结论依据；v6 是修复后的新证据，实验文件继续保留以便审计。
