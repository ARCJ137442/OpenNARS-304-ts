## 任务过程笔记

- “marker 已出现”不能覆盖后续异常；runner 的 functional_pass 必须同时满足无异常、无 timeout、marker 完整和 parity。
- equalityBuckets 是后续性能优化相对于稳定冻结版本新增的快速路径；本轮首先采用可迭代快速路径、异常桶回退全表 Java equals 扫描的兼容修复，避免把异常形状当作“键不存在”。
- 交互式 shell 不调用 Nar.start 后台线程，而是用 Nar.cycles(N) 逐步推进，满足本阶段单线程功能复核和低资源约束。
- 本次延长复核只用于区分“仍在推进但慢”和“无进展/功能错误”：marker 仍优先于周期上限，过程异常不能由已出现 marker 抵销。
- `nars_multistep_2.nal` 最终观察到 203055 周期；Java/TS marker 均完整，marker 路径判定等价。TS 运行约 365881 ms，Java 约 5570 ms；这是待后续性能优化的量化基线，不改变当前功能结论。
- shell 警告的两个根因分别是 Node `--experimental-loader` 入口和 jree 1.3.0 缺少标准 ESM `exports`；二者已通过 `--import`/`register()` 与启动前幂等元数据补丁消除。Node 测试器自身的 `--experimental-strip-types` 提示仍属于测试启动器提示，不会出现在 shell 子进程 stderr。
- Java runner 的 manifest 依赖缺失曾被误判为 Java 语义失败；补齐依赖后，关闭 progress observer 的 stability Java-only 运行通过，随后将 observer 限定为 `CycleEnd`，避免长运行输出事件回调改变行为。
