## 建议的集中修复顺序

1. **共享 jree/API 边界**：先核对 `System.Logger`、集合、反射、JavaString、boxed 数值、MJS 声明的真实运行时能力；这一层会减少多个测试和 production 簇。
2. **JavaString/CharSequence 与 boxed number/bigint**：建立集中转换/构造函数并补局部单测，禁止各测试文件自行 `as unknown as`。
3. **Java 重载与构造入口**：按类族补齐 overload，尤其是 `NullOperator`、`Reflect`、Narsese 和测试构造器。
4. **可空控制流**：沿 Java `null` 返回契约传播，区分合法空结果与真正异常；不得用非空断言批量消音。
5. **测试导入与测试辅助层**：按测试目录批量恢复显式 import、静态 helper、输出条件和 runner 类型；处理 `$outer`/`org` 等迁移生成痕迹时逐类验证。
6. **unknown/implicit-any、初始化、泛型和孤立项**：在共享接口稳定后收尾，避免反复改测试签名。

每个批次仍须：记录前后数量 → 对照 Java → 最小修复 → 非增量 tsc → 串行测试 → 触及运行时则局部 parity/NAL → 编码检查 → 独立提交推送。
