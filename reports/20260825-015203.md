## 已确认事实

- jree 1.3.0 的 `java.lang` 模块命名空间是不可扩展的模块 namespace，且没有导出 `Double`；直接给 `java.lang.Double` 注册运行时属性会抛出 `Cannot add property Double, object is not extensible`。
- 当前 Java→TypeScript 代码在生产 `Nar` 和旧测试/性能代码中使用了 `java.lang.Double` 的 boxed API；缺失声明造成 `TS2694`/`TS2339`，并阻断非增量诊断。
- Java 这些位置的数值实际参与的是 double 运算、集合记录或静态 Infinity/toString 操作；没有证据表明必须依赖 jree 的对象身份。
- 本批基线为 1681 项：生产 742、测试 939；canonical Java artifact 未改变，SHA-256 仍为 `2CF519E1F85C38E38384C7076AA750C730580C612C97CC70C70B361361F273F5`。

## 本批决策

- 在 `src/runtime/jree-compat.ts` 增加显式 `JavaDoubleCompat`，集中承载 `valueOf`、`toString`、`doubleValue`、`floatValue` 和 Infinity 常量。
- 生产 `Nar` 的阈值解析改用该兼容类；集合/指标/性能测试中仅需要数值的 `Double` 泛型改为 TypeScript `double`，保留 Java 的数值语义和自动装箱后的实际用途。
- 放弃修改冻结的 jree namespace；删除未生效的 ambient augmentation 和运行时注册尝试，避免污染第三方模块或留下运行时崩溃。

## 任务过程笔记

- “补全 jree namespace”必须先验证模块对象是否可扩展；静态声明扩展和运行时属性注入不是同一件事，不能只让 tsc 通过。
- boxed number 的迁移要按用途拆分：需要 Java 包装行为的入口集中到兼容类；只存储/计算 double 的集合可以用原生 `double`，避免制造虚假的对象身份依赖。
