## 任务过程笔记

- 📌 Java 304 的 `Term.get` 对坐标文本采用整数识别；`-1.0`、`0.0` 等小数坐标必须保留为概念文本，交由 `Nar.dispatchToSensoryChannel` 映射。TS 不能用更宽的正则“顺手增强”语义，否则会改变分派路径。
- 📌 Java 的 `SetExt.toString()` 语义不能直接假定 TS 对象的 `.toString()` 相同；迁移边界应使用领域命名方法 `name()`，并避免把 Java 正则转义字符串（如 `"\\["`）原样当作 JS `split` 分隔符。
- 📌 `java.lang.Double.parseDouble` 在当前 jree Node runtime 中不是可调用实现；数值解析应在 Node 适配边界使用 `Number.parseFloat`，而非伪造 Java 静态 API。
- ⚠️ VisionChannel 接通后，完整 vision 场景不再是“插件未加载所以快速完成”，而是真正进入高负载推理；局部 5×5 矩阵通过不等于 50000 周期 marker 通过，后续需单独测量任务增长和内存来源。
- 📌 本批将 `timeout`、`process_limit`、`exception`、`marker_missing` 分开解释：detective2 是 process limit；vision 复核是人工安全停止；两者都不能被写成 no-progress timeout。 :codex-annotation{index="1"}
