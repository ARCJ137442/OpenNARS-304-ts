## 过程经验

- `jree` 的 `Integer.parseInt` 与 Java 304 的 `Integer.parseInt` 在空白处理上并不等价；本批证明“去 jree”不能只按 API 名称替换，必须以 Java 依赖版本的真实合同为准。
- `StringUtils.isNumeric` 的语义是非空 ASCII 数字串，不是“trim 后可解析为数字”；将两者混同会改变 operator 的异常路径。
- 异常类的新增触及 `jree-compat`，因此责任归属仍是 J4 主簇、J1 支持簇；但没有因此扩大到 M1-。
- 受影响 NAL 只作为局部活跃链哨兵；023/J4 收口、责任簇切换或阶段验收仍需按门禁重新执行更大范围回归。
