## 任务过程笔记

- `run-nal-corpus` 的 ENOENT 属于一次错误资源根目录的调用；不能用单条失败日志代替可恢复结果证据。连续 chunk 和资源分类才是“已启动并遍历”的直接证据。
- Java `long` 在 jree 类型层是 `bigint`；测试桩中的 `time()`、`TemporalRules.order` 和随机种子必须显式使用 bigint，不能仅靠运行时 number 兼容。
- Java 的 `NarNode.EventReceivedTask` 是每个实例上的事件类，测试应使用 `nar2.EventReceivedTask.class`，不能引用不存在的静态成员。
- `assert.ok`/`assert.equal` 不总能让 TypeScript 对动态导入的联合类型完成收窄；对 `parseTerm`、可空通道和 truth 使用显式 guard 更稳定。
- `CompoundTerm.extractIntervals` 和 `Anticipate.anticipate` 的实现本来就处理 null，因此把签名补成可空是契约修正，不是推理算法改写。
