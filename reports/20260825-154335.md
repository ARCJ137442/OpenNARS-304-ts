## 任务过程笔记

- `run-nal-corpus` 的 ENOENT 属于一次错误资源根目录的调用；不能用单条失败日志代替可恢复结果证据。连续 chunk 和资源分类才是“已启动并遍历”的直接证据。
- Java `long` 在 jree 类型层是 `bigint`；测试桩中的 `time()`、`TemporalRules.order` 和随机种子必须显式使用 bigint，不能仅靠运行时 number 兼容。
- Java 的 `NarNode.EventReceivedTask` 是每个实例上的事件类，测试应使用 `nar2.EventReceivedTask.class`，不能引用不存在的静态成员。
- `assert.ok`/`assert.equal` 不总能让 TypeScript 对动态导入的联合类型完成收窄；对 `parseTerm`、可空通道和 truth 使用显式 guard 更稳定。
- `CompoundTerm.extractIntervals` 和 `Anticipate.anticipate` 的实现本来就处理 null，因此把签名补成可空是契约修正，不是推理算法改写。
- 旧 Java 测试依赖 JUnit 参数化运行器，但当前 TypeScript 工程没有 JUnit 实现；显式串行适配比补一组空壳 `JUnitCore` 类型更诚实，也符合低内存运行约束。
- `BagIteratorTest` 的剩余诊断不是 Bag 算法错误，而是转写文件漏掉 Java 原测试的三个依赖导入；修复只恢复测试表达，不改 Bag 的调度或哈希行为。
- 正式构建采用“tsc 权威检查 + TypeScript `transpileModule` 产物化”两步：前者负责完整语义诊断，后者只负责保持 ESM 结构与导入扩展名可运行，避免把无类型检查的转译结果冒充类型安全。
- clean install 后的 npm 包 dry-run 共 257 个文件，包版本为 `0.1.0`；`dist/` 只作为可重建产物保留在 `.gitignore` 中，不把生成二进制混入源码提交。

- 使用 JavaString/Java long/集合泛型；按 Parser 异常类型拆分 catch；对 `Sentence.truth` 可空分支显式返回。
- 目的：消除旧指标测试的迁移类型漂移，保持其既有观测逻辑。

### `test/core/NarNodeTest.ts`、`test/core/bag/DistributorAnalyzer.ts`、`test/core/TermTest.ts`、`test/entity/TLink.test.ts`

- 修正 primitive/generic/只读数组边界，并使用实例事件类和 jree 已提供的 LinkedHashSet。
- 目的：让旧测试代码表达真实 Java 类型，不引入新的运行时兼容层。

### `test/core/ReplaceIntervalTest.ts`、`test/core/SaveLoadMemoryTest.ts`、`test/node/*.test.ts`

- 对 parseTerm、Negation、Image、VisionChannel、TaskLink、变量替换和 long 值增加显式收窄或 Java 包装。
- 目的：修正测试桩自身的 TypeScript 诊断，保持局部算法/迁移契约测试可编译。

### `src/operator/mental/Anticipate.ts`、`src/language/CompoundTerm.ts`

- 将实现已经支持的 null 输入反映到公开签名。
- 目的：对齐 Java 允许的可空调用契约，不改变推理分支。

### `test/util/serial-parameterized-runner.ts`、`test/core/NALTest.ts`、`test/core/NALTestSome.ts`、`test/core/StabilityTest.ts`

- 用显式串行参数循环替代不存在的 JUnitCore/ParallelComputer/Result；失败用例写入 Java Boolean 状态并继续后续用例。
- 目的：恢复旧测试入口的真实执行语义，并避免引入未实现的测试框架假象。

### `test/node/serial-parameterized-runner.test.ts`

- 验证串行运行器会完整执行所有参数、独立回调失败并继续后续参数。

### `test/core/bag/BagIteratorTest.ts`
