1. Java 的 `Map.get` 缺失值和 TypeScript `Map.get` 缺失值不是同一运行时值；这类差异会通过 `=== null` 传播到时间戳和任务调度。
2. Java 的继承重载在 TypeScript 中必须人工恢复，尤其是“子类覆写无参方法、父类保留带参数方法”的组合。
3. `instanceof` 的类族语义比运行时名字更稳定；时间关系和并行/空间合取必须显式建立类型映射。
4. 避免循环依赖不能以牺牲 Java 运行时类型判断为代价；窄的注册接口可以把初始化顺序和类型语义同时保住。
5. `toothbrush.nal` 当前 Java 为 2/2 marker、TypeScript 为 1/2；局部修复有效，但仍有独立的应用级任务派发差异，不能宣布整机完成。
